# fixtures/parsers/xlsx_pmd — SOURCE

Fixtures for `parserXLSX_PMD` (Excel workbook variant of PMD). The parser is a thin
wrapper: `XLSX.read(bytes)` → `xlsx_to_csv(workbook)` → `parseCSV_PMD`. So these
fixtures mirror `csv_pmd/` cell-for-cell; each reference equals its `csv_pmd` sibling
except `metadata.name` (which echoes the `.xlsx` filename).

## Layout

- `real/` — real `.xlsx` files. Empty: no real `.xlsx` exist on disk (users export
  them on demand). Deferred to a follow-up via a PMTools export run — see PR 3 in
  [part-a-pr-plan.md](../../../../../.claude/development-roadmap/part-a-pr-plan.md).
- `synthetic/` — generated by [`scripts/generateXlsxFixtures.js`](../../../../../scripts/generateXlsxFixtures.js)
  (numbers as native numeric cells, the shape a real Excel/PMTools export produces).

## Real-file origins

_Deferred — populated by an export run in a follow-up PR (see PR 3 plan)._

## Synthetic-fixture matrix

| File | Sheets | Locks |
|------|--------|-------|
| `thermal_and_af.xlsx` | `data` | happy path: thermal + AF steps, NRM/T/M demag symbols, the `csv_pmd` data through the XLSX read path. |
| `with_empty_second_sheet.xlsx` | `data`, empty `notes` | the only XLSX-specific behavior: `xlsx_to_csv` concatenates sheets but skips empty ones (`if (csv.length)`), so this parses identically to `thermal_and_af`. |

Formula/date/hidden-column/merged-cell variants are a possible future addition; the
CSV parser numifies every value, so they would not change the parsed output unless a
cell value itself changes.
