# fixtures/computations/fold_unfold — SOURCE

Reference-output fixtures for the **deterministic core** of the bootstrap fold test —
`findBed` + `unfold`, exported from
`src/utils/statistics/PMTests/FoldTest/foldTestBootstrap.ts`. This is "Layer A" of the
fold-test coverage strategy (see `.claude/development-roadmap/part-a-pr-plan.md`): lock the
randomness-free math now, before the Step-3 refactor that extracts the seeded full pipeline
(`runFoldTest`, "Layer B", fixtures under `src/__tests__/fixtures/fold_test/`).

Driven by the shared computation harness (`describeComputationReferenceOutput`); the test is
`src/utils/statistics/PMTests/FoldTest/__tests__/foldTestDeterministicCore.test.ts`.

## Provenance

Generated by `scripts/gen_foldtest.py` (seed 42, reproducible). A tight Fisher cluster of
"stratigraphic" (pre-fold) directions is re-folded site-by-site with PmagPy's `dotilt`, so
the geographic directions are scattered and the **geologically correct best-unfolding
optimum is ~100 %** (100 % on the 10 % untilting grid PMTools and the cross-check both use;
~98 % on a finer grid, from the 0.1° direction rounding). The cross-check is a fair test
because `findBed` provably recovers bedding in the same convention PmagPy's `dotilt`
consumes (verified). Re-run with `python3 scripts/gen_foldtest.py --force`.

## Cases

- `synthetic_fold_saved_iteration` — `iteration: 0` → the full per-step `taus` curve is
  captured (the `iteration < 24` branch of `unfold`).
- `synthetic_fold_unsaved_iteration` — `iteration: 24` → `taus` stays empty, only the index
  is reported (the other branch). Same directions as above.

## PmagPy cross-check — and the bug it exposed

`synthetic_fold.pmagpy.json` records PmagPy's fold-test curve on the same data: tau1 rises
monotonically 0.61 (0 %) → 0.96 (100 %), optimum **100 %**.

PMTools' `unfold` on the identical geo/strat pairs locks **index = −17 %**, with tau1
*falling* 0.61 → 0.44 across 0 → 100 %. Both agree exactly at 0 % (0.6083) but move in
opposite directions. This is a **confirmed PMTools bug** (locked as-is per the Part A
golden-master discipline; documented in
`.claude/development-roadmap/notes/found-bugs-todo.md`, "Surfaced in Layer A"):

> `findBed` returns a dip-direction (`azimuth = strike + 90`); `unfold` then passes that
> azimuth straight into `Coordinates.correctBedding`, whose first parameter is a **strike**
> (it computes `dipDirection = strike + 90` itself). The 90° mismatch unfolds about the wrong
> axis, so clustering is maximised near 0 % instead of the true 100 %.

The cross-check is what surfaced it: a plain golden-master would have silently enshrined the
wrong answer. When the convention bug is fixed, these fixtures go red and must be regenerated
(the locked index should become ~100 %).
